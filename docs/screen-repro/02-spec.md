### 記号・座標系の定義(全章共通)

| 記号 | 定義 |
|---|---|
| `D` | レース距離(m)。既存 `race.dist`(1200〜3600 等) |
| `leadM` | 先頭馬の走破距離(m)。`Math.max(...posAt(t))` |
| `R` | 残距離 = `D - leadM`(m) |
| `p` | 経過率 = `leadM / D`(0〜1) |
| `posAt(t)` | 既存の各馬走破距離配列(m)。線形補間済み |

| `VW,VH` | 1ビューの論理解像度 = 1280 × 720 |
| `DW,DH` | デュアル論理キャンバス = 2560 × 720。HUD 座標の基準系 |
| `FL` | 焦点距離(px)。FOV への換算 `fovY = 2·atan((VH/2)/FL)`。基準 830 |

## 1. 画面仕様

### 1.1 レイヤー構成

WebGL 経路では 2 レイヤー(WebGL + HUD)を基本とし、フォールバック経路のみ従来 3 レイヤーを使う。

| z | レイヤー | 実体 | 解像度(論理) | 役割 |
|---|---|---|---|---|
| 0 | `bgCanvas`(2D) | `<canvas>` | 2560×720 | **WebGL経路では未使用(非表示)**。フォールバック時のみ空・地面を 2D 描画(§8) |
| 1 | `glCanvas`(WebGL) | `<canvas class="layer">` | 2560×720 ×DPR | 3Dシーン本体。1フレームに左右2ビューポートを描画(§1.3)。空・地形・ラチ・馬・美術・グレアを全て内包 |
| 2 | `fgCanvas`(2D) | `<canvas class="layer">` | 2560×720 | HUD 一式(§2)。等倍(DPR非依存、テキスト鮮鋭度優先) |

- 既存 CSS(`.canvas-wrap.tv canvas.layer { position:absolute; inset:0; width:100%; height:100% }`)をそのまま流用。`bgCanvas`/`glCanvas`/`fgCanvas` の生成順・重ね順を上表に合わせる。
- キャンバスの `width`/`height` 属性を現行 1280×720 から **2560×720** へ変更(`glCanvas` は後述 DPR を乗じる)。論理サイズはコンテキストスケールで吸収し、描画コードは論理 2560×720 系で書く。

### 1.2 物理解像度と DPR(§9「物理解像度・DPR」の確定)

- **決定: 単一横長キャンバス方式(2560×720)を採用**。理由: (a) HUD が両ビューをまたぐ帯・スライド数字・分担凡例を持ち、1枚の座標系で描くのが最も単純(要件§1-B)、(b) WebGL レンダラーは 1 個で済み `renderer.setViewport/setScissor` による 2 パスでコンテキスト切替コストを避けられる。
- `glCanvas` の物理バッキングストア = `2560·q × 720·q`(`q` = 品質DPR)。`q ∈ {1.0, 0.75, 0.6, 0.5}` を E-15(§7)が制御。初期値は `Math.min(window.devicePixelRatio||1, 1.0)`(高DPR端末でも 1.0 上限=横2560で十分)。
- `fgCanvas` は常に等倍 2560×720(HUD 文字の可読性を優先)。
- CSS 表示幅はコンテナ 100%。要素比率は 2560:720 = 32:9。`.canvas-wrap` の `height:auto` で高さ追従。

### 1.3 デュアルビューのビューポート分割

- 左ビュー = `x∈[0,1280)`、右ビュー = `x∈[1280,2560)`、各 720 高。境界に 4px の暗色セパレータ(`#0a0e12`)を `fgCanvas` に描く(参考画像の 2 画面間の黒枠様式)。
- WebGL 描画(毎フレーム):
  1. `renderer.setScissorTest(true)`
  2. 左: `setViewport(0,0,1280·q,720·q)` / `setScissor(同)` → `camera.aspect=1280/720` を左カメラ解へ設定 → `render(scene,camL)`
  3. 右: `setViewport(1280·q,0,1280·q,720·q)` / `setScissor(同)` → `render(scene,camR)`
- 同一 `scene` を 2 回描画(要件§2 前提「同一シーンを1フレームに2ビューポート」)。馬の位置・ポーズ更新はビューポート描画の**前に1回だけ**行う(§6.5)。
- **単一ビュー縮退時(E-15 stage4)**: 左ビューのみ全幅 `setViewport(0,0,2560·q,720·q)`(aspect=2560/720)で描画し、右ビュー HUD 領域を隠す。`SH._rvState.qualityLevel=4` を記録(§7・AC-1)。

### 1.4 モバイル表示

- 目標 30fps(要件§0-5)。初期化時に `navigator.hardwareConcurrency<=4` もしくは粗いタッチ判定でモバイル級と推定し、E-15 の初期段階を stage1(影オフ)から開始してよい。
- コンテナ幅にフィット(32:9)。縦持ちスマホでは物理表示高が小さくなるため、HUD 最小フォントは論理 28px(=720p 換算 14px 以上、§2)を死守。
- タッチ操作は既存の `fgCanvas` クリック(フェーズスキップ)を流用。マルチタッチ・ピンチは非対応(スコープ外)。

## 2. HUD 仕様(全10要素)

座標は論理 2560×720 系。フォントは全て `sans-serif`(端末内蔵)を使用しファイル追加なし。数値は 720p 相当での実測比率に基づく。フェード曲線は特記なき限り **ease-out**(`a = 1-(1-u)²`, `u∈[0,1]`)。

### 2.0 放送HUD のフェーズ管理(§9・§3補足の確定)

- 状態変数 `hudPhase ∈ {"pre","fadein","on"}`。しきい値は **`view.t` 実測ではなく `p`(経過率)基準**で正規化し、距離不変にする。
  - `pre`: `p < P_HUD_ON`
  - `fadein`: `P_HUD_ON ≤ p < P_HUD_ON + ΔP_FADE`(進行に伴いアルファ 0→1)
  - `on`: それ以降ゴールまで
- 確定値: **`P_HUD_ON = 0.085`(発走直後の約8.5%地点でフェード開始)、`ΔP_FADE = 0.020`(=フェード区間、約2%進行 ≒ 実測1.0〜1.6秒相当)**。
  - 根拠: 参考 #5(`'17`)で既に表示済み・#1〜#4(`'03`〜`'08`)で未表示。2000m・先頭16m/s 換算で `'08〜'17` は `p≈0.06〜0.14`。この窓の入口 0.085 を開始点とする。
  - AC-4/AC-5/AC-11 の「目安10〜17秒でフェードイン」を満たす(距離により秒は前後するが `p` 一定)。
- フェード対象 = **H-1 / H-2 / H-3(+H-4) / H-8**。非対象(発走時=`view.t≥0` から常時表示)= **H-5 / H-6**。H-7/H-9/H-10 は各自のトリガ。

### 2.1 要素別仕様

凡例: 座標は `(x,y)` 左上原点。`αHUD` = §2.0 のフェードアルファ。

#### H-1 上部帯
- 位置/サイズ: `x=0, y=0, w=2560, h=60`(=画面高 8.3%、要件「7〜9%」内)。両ビュー全幅を横断。
- 背景: 芝色系の緑グラデーション(上 `#2f8f3a` → 下 `#256f2c`)にアルファ `0.82·αHUD`。下端に 3px の明線 `rgba(180,230,170,0.5)`。
- 更新: `hudPhase` に従いフェードイン。以降ゴールまで常時。毎フレーム再描画。

#### H-2 残距離数字(スライド)
- 内容: `Vshow = Math.ceil(R/100)*100` を「白抜き数字+左脇に紅白縞ポールアイコン」で表示(1700→1600→…→100→ゴール直前で消灯)。
- スタイル: フォント `bold 46px`、白 `#ffffff`、縁取り `#0c2a12` 幅 5px + 影 `rgba(0,0,0,0.4)` (オフセット2,2)。ポールアイコン = 幅7・高44 の紅白(`#e03131`/`#ffffff`)3段縞、数字左に 10px 間隔。
- **スライド則(§9 第一候補を確定)**: 「次の100m標識へ向けた線形移動+ビュー間ワープ許容」。
  - `f = (R mod 100)/100`(次の下位標識までの残り率、1→0 で標識に到達)。
  - 帯内の水平トラック `xTrack ∈ [X_L, X_R]`、`X_L=380`(左ビュー左寄り)、`X_R=1580`(右ビュー中央左)。
  - `xNum = X_R - (1 - f)·(X_R - X_L)`(f=1 で右端 `X_R`、f→0 で左へ移動)。
  - `f` が 1.0 へロールオーバー(100m通過=数字が1段減る)した瞬間、`xNum` は `X_R` へ**ワープ**(瞬間移動、補間なし)。これがビュー境界(x=1280)をまたぐ動き(AC-18)を生む。
  - 垂直位置 `yNum = 46`(帯内中央、ベースライン)。
- 更新: 毎フレーム位置計算。値は `R` と ±100m 未満で一致(AC-4)。`R≤0` で非表示。

#### H-3 隊列チップ(盾形)
- 位置: 帯内右側、残距離数字と非重複の領域 `x∈[X_R+70, 2540]`(右詰め、右端から左へ並べる)。
- 表示頭数(§3補足の確定): **順位順に先頭から最大 8 頭のウィンドウ**。`n≤8` は全頭。`Nchip = Math.min(n,8)`。
- レイアウト: 右端 `x=2540` を先頭(1位)基準に、左方向へ `Nchip` 個。チップ幅 `cw`、間隔 `gap=6`。総幅が領域を超える場合 `cw` を自動縮小(`cw = clamp((2540-(X_R+70))/Nchip - gap, 30, 46)`)。高さ `chH = 44`(帯内)。
- **盾形状(shield)描画仕様**(2D Canvas パス、チップ左上 `(cx,cy)`、幅 `cw`、高 `chH`、角丸 `r=6`、下部尖り深さ `tip=10`):
  ```
  moveTo(cx+r, cy)
  lineTo(cx+cw-r, cy); arcTo(cx+cw,cy, cx+cw,cy+r, r)      // 右上角丸
  lineTo(cx+cw, cy+chH-tip)                                 // 右辺
  lineTo(cx+cw/2, cy+chH)                                   // 右下→尖端
  lineTo(cx, cy+chH-tip)                                    // 尖端→左下
  lineTo(cx, cy+r); arcTo(cx,cy, cx+r,cy, r)                // 左上角丸
  closePath()
  ```
  塗り = `WAKU_COLORS[waku-1]`、外周線 `rgba(0,0,0,0.45)` 幅1.5。番号 = `bold (chH*0.5)px`、色 `WAKU_TEXT[waku-1]`、中央(尖り分を避け `cy+chH*0.46` ベースライン)。
- 順位判定: 走破距離ベース(`posAt` の降順)。順位変動時、対象チップは 0.35 秒(ease-out)で新スロット `x` へスライド(AC-5「1秒以内」を満たす)。毎フレーム evaluate。

#### H-4 自馬タグ(隊列チップ)
- 自馬(`r.kind==="owned"`)のチップ直上 `y = cy-16` に小ラベル(幅=チップ幅、高14)。地 `#f76707`(橙)角丸、文字 `bold 12px #fff` で現在順位(例「3」)。
- 自馬チップ本体を 1.15 倍拡大(高 `chH·1.15`、下方向へ拡張)。順位変動に追従。

#### H-5 出走馬凡例
- 位置: 各ビュー下部。左ビュー `x∈[24,1256]`、右ビュー `x∈[1304,2536]`、`y∈[VH-96, VH-8]`。
- **左右分担規則(頭数可変で一般化)**: 全 `n` 頭を **6 列固定 × `Rrow=ceil(n/6)` 行**の行優先グリッドに敷く。セル `(row,col)` の馬番 = `row*6+col+1`(1始まり、`n` 超は空セル)。**左ビュー=列0〜2、右ビュー=列3〜5**。
  - 12頭: 左=1,2,3/7,8,9、右=4,5,6/10,11,12(参考 #5 と一致)。
  - 18頭: 3列×3行/ビュー(左=1-3/7-9/13-15、右=4-6/10-12/16-18、AC-17a)。
  - 5頭: 左=1,2,3、右=4,5(空セルは描かず崩れない、AC-17d)。
- チップ: 枠色角丸(`r=4`)地 `WAKU_COLORS`、馬番 `bold 22px` 色 `WAKU_TEXT`、右に馬名 `16px` 白+黒縁取り1.5px。1セル = 幅約 200・高 40。自馬セルは橙タグ(H-4様式)付き。
- 更新: 発走前〜ゴール後まで常時(フェード対象外)。順不同(馬番固定)。

#### H-6 経過タイム
- 位置: 左ビュー左下、凡例の上 `(40, VH-116)`。
- 表示: `'03`/`'56`/`1'15` 様式(`m'ss`、分=0 は省略し `'ss`)。`fmtElapsed(sec)` を新設(既存 `fmtTime` は `m:ss.d` で別用途のため流用不可)。

#### H-7 1000m通過タイム

#### H-9 自馬頭上マーカー(3D空間内)
- 実装: WebGL シーン内の専用 `Sprite`(または平面メッシュ)を自馬 `group` にアタッチ。頭上 `y = 2.5m`(馬体スケール後)、上下浮遊 `±0.12m`(`sin(t·1.4)`)。
- 形状: **黄色ひし形〜下向きピン**の様式(下向き五角形ピン推奨)。CanvasTexture 96×112、地=発光黄 `#ffd21a`、外周 `#8a6a00` 2px、中央に馬番 `bold 48px #3a2a00`。
- **遮蔽なし**: `material.depthTest=false`、`depthWrite=false`、`renderOrder=999`。両ビューポートで最前面。
- サイズ: カメラ距離減衰(スプライトの `scale` を距離 `z` に反比例)だが最小 24px 相当を保証(`scale = clamp(k/z, minScale, maxScale)`)。自馬非出走レースでは生成しない。

#### H-10 スタート/ゴール系バナー
- 既存 `banner()` を流用。**全幅中央**(2560系では `x=1280` 中央)にオーバーレイ。「各馬ゲートイン」「スタート!」「写真判定」「1着 …」。既存フェーズ準拠(§6)。デュアル時も両ビューにまたがる 1 枚として重畳。

### 2.2 共通制約
- 全テキスト最小フォント高 = 論理 28px(720p 実表示で 14px 相当以上、AC-17c)。
- H-2 と H-3 は帯内で非重複(H-3 の左端 ≥ `xNum + 数字幅 + 40`。重なる場合 H-3 の `cw` を先に縮小)。
- 色は全要素で `WAKU_COLORS`/`WAKU_TEXT` を唯一の枠色源とする(凡例・隊列・掲示板一貫、AC-6)。

## 3. カメラ仕様

各ショットは `course.pos(m, lat, y)` で位置・注視点を与える。`m` は基準 `packC = leadM - 8`(先頭集団中心)または `leadM`/固定 `m` を用いる。焦点距離 `FL` と切替条件を数値化。同一ショット内は既存 lerp 追従(位置 0.14、注視 0.2、`FL` 0.1)。ショット切替は**ハードカット**(`camMode` 変化で lerp をリセット)。

### 3.1 左ビュー(可変・追走カメラ)ショット一覧

`packC = leadM - 8`。距離は m、`y` は高さ m。切替は `p` 主体。

| ID | 発動条件 | 種別 | 位置 `pos(m,lat,y)` | 注視 `pos(m,lat,y)` | FL | 揺れ(sway) |
|---|---|---|---|---|---|---|
| L0 | `t<0` | ゲート正面〜斜め | `(16, +2, 2.4)` | `(0, 0, 1.4)` | 1100 | 0 |
| L1 | `0≤p<0.08` | 地上側面(低・ラチ越し) | `(packC+6, +14, 1.9)` | `(packC, 0, 1.5)` | 830 | 0.22 |
| L2 | `0.08≤p<0.25` | 引き側面⇄ミドル | 交互: 引き `(packC+2, +26, 4.0)` / 寄り `(packC+5, +12, 1.8)`(3秒ごと) | `(packC, 0, 1.6)` | 830 | 0.18 |

### 3.2 右ビュー(定点カメラ列)配置と先回りロジック

右ビューは**三脚固定(揺れ0)**。コース沿いに仮想定点カメラ列を敷き、先頭が現定点を通過しきる少し前に次定点へハードカット。

- **配置間隔**: `CAM_SPACING = 200m`(要件「150〜250m」中央)。定点 `k` の設置 `m` = `Mcam(k) = k·200 + CAM_OFFSET`(`CAM_OFFSET=40`)。カメラ位置は設置 `m` に対し `pos(Mcam, latC, yC)`。
- **定点の型(巡回)**: 各定点は下記からラウンドロビンで型付け。位置/注視/FL:

| 型 | 位置 `pos(Mcam,lat,y)` | 注視 | FL | 備考 |
|---|---|---|---|---|
| R-front(正面) | `(Mcam+40, 0, 2.4)` | 先頭集団 `(leadM,0,1.6)` | 1100 | 馬群が向かってくる(#1様式) |
| R-side(側面望遠) | `(Mcam, +22, 3.2)` | 集団 `(packC,0,1.6)` | 1400(圧縮) | パン追従(位置固定・注視のみ追う、#7/#9) |
| R-diag(斜め正面) | `(Mcam+25, +16, 5.5)` | `(packC,0,1.6)` | 950 | 中団俯瞰(#12) |
| R-name(名物) | §4 の名物定点座標 | 名物構造物+通過馬 | 名物ごと | 石橋横/紅白ポール際/スタンド前(必須経由) |
| R-goal(ゴール横) | `(D-6, +14, 3.0)` | `(D,0,1.6)` | 1000 | ゴール柱を画面内(#19様式) |

- **先回り(次カメラ選択)ロジック**:
  - 現定点 `k` の設置 `m = Mcam(k)`。先頭が `Mcam(k) + LEAD_PASS`(`LEAD_PASS=25m`、通過しきる直前)に達したら、`k' = k+1`(=前方200m)へカット。
  - カット直後、馬群は次定点にまだ到達していない → **空フレーム**(空舞台)。空フレーム許容 `EMPTY_MAX = 3.5s`。3.5秒を超えても馬群未到達(=先頭が遅い)場合は `k` を先頭寄りへ再同期(`k = floor((leadM-30)/200)`)して空フレームを打ち切り。
  - 「馬群が通過→数秒で次カメラの空フレーム」を 60 秒あたり 3 回以上生む(AC-2)。200m 間隔・16m/s では約 12.5 秒毎にカット ≒ 60 秒で 4〜5 カット。
- **名物定点の強制経由**(要件 R3): 石橋区間・紅白ポール区間・スタンド区間に対応する `Mcam` は型を強制的に R-name にする(§4 の配置表に基づき `Mcam` 近傍を判定)。1レースにつき各1回以上経由。
- **自馬フレームイン保証(P1/AC-23)**: 30 秒に 1 回以上、`R-side` の注視を「先頭集団」から「自馬」に切替(自馬が中団以下でも)。実装: `lastOwnInView` を保持し、経過 25 秒で次カットの注視を自馬 `pos(ownM,0,1.6)` に固定、`ownM` がフレーム内に入るよう定点 `k = floor((ownM-30)/200)` を選ぶ。
- **カット条件まとめ**: (a)先頭が `Mcam+25` 到達、(b)空フレーム 3.5 秒超、(c)自馬フレームイン要求(25秒経過)、(d)名物区間侵入、(e)`R≤200` で R-goal へ固定。優先度 e>d>c>a>b。

### 3.3 両ビュー共通制約
- **同一カメラ位置の禁止**(要件§2.3): 左右のカメラ `pos` 間距離が 12m 未満かつ注視方向内積 >0.98 の場合、右ビューを次定点へ強制カット。
- **両方同時空フレームの制限**: 左が L4/L5(馬群外)かつ右が空フレームになる状況は、右の空フレーム判定で回避(左が馬群外の間は右のカットを 1 秒抑止)。
- リプレイ・掲示板は全幅1画面へ復帰(§6・既存様式)。

## 5. 照明仕様

シーンは `race` 属性で **ナイター/昼**を選択(`SH.isNightRace(race)`)。

- **ナイター選択条件(E-12 の確定)**: `race.grade === "WBC"`(参考の WBC CLASSIC がナイター様式) **または** 季節終盤の特定重賞(`race.week >= 48 && race.grade === "G1"`)。それ以外は昼。判定は `data.js` に `SH.isNightRace = function(race){ return race.grade==="WBC" || (race.week>=48 && race.grade==="G1"); }` を追加(既存値不変)。

### 5.1 ナイター(基本)
- 空: 濃紺→黒の頂点グラデーション(上 `#0a0e1e` → 地平 `#1a2436`)。月(発光白円)1個 + 星少量(点スプライト 40 個程度)。
- ライト: `HemisphereLight(0x2a3550, 0x0e1a12, 0.35)`(全体を暗く)。照明塔ごとに `PointLight`(色温度 5600K 相当 `0xfff4e0`、減衰付き、走路を局所照明)を S 区間の塔位置に 4〜6 灯。走路が明るく周辺が暗い明暗差(E-10)。
- フォグ: `FogExp2(0x121a2a, 0.0016)`(遠景を夜霞へ)。
- グロー近似(E-14, ポストプロセスなし): 照明塔・月に **加算ブレンド `Sprite`**(放射状ハロ CanvasTexture、`blending=AdditiveBlending`)。右ビュー定点では画面内に光条スプライト(十字グレア)を許容(要件 R1/E-10)。
- 影: 多灯による淡いブロブ影のみ(shadowMap 不使用でも可)。

### 5.2 昼(他レース)
- 空: 既存 `skyColors(cond)` の配色を WebGL 頂点色/背景へ移植(良=青空 `#3f96de→#c2e5ff`、不良=灰 `#39424e→#67727f` 等)。雲ビルボード数個。
- ライト: `HemisphereLight` + `DirectionalLight`(太陽、既存 `buildScene` の晴/曇/雨トーンを流用)。良馬場は暖色 `0xfff2dd` 0.95、不良は寒色弱め。
- フォグ: `Fog`(遠景大気霞、既存 `hazeOf` 相当)。雨は既存 `sky.rain` の前面 2D 線を `fgCanvas` に描画。
- グロー: 昼は軽微(ハイライトのみ)。

### 5.3 区間トーン(E-11)
- 環境光(`HemisphereLight.intensity`/色)を区間 `p` でゆるやかに補間: 竹林 S1・森 S2・暗森 S6 は暗め(intensity ×0.8)、丘陵 S5・橋 S3 は明るめ(×1.15)。1 フレームあたり 0.02 で lerp(急変を避ける)。
- 画作り(E-14): 軽いビネット(既存キャッシュ `vig` を `fgCanvas` へ流用、2560幅へ再生成)。

## 6. 馬体・アニメ仕様

`horse3d.js` を拡張(既存プロポーションを実馬比へ調整)。単位 m、ローカル +X 進行方向。

### 6.1 プロポーション(A-1)
- 体高(き甲まで)≈ 1.6m、体長(胸端〜臀端)≈ 2.4m、脚は細く長い。既存 `H3_SCALE=1.45` を見直し、素体を実寸で作り視認スケールは別途 `1.15` 程度に抑える(密集破綻回避)。
- 首〜胴〜臀を滑らかに: 既存の球体3分割(torso/chest/rump)を、接合部を重ねて連続シルエットにする(角張り解消、A-1)。セグメント数は E-15 stage3 で削減。

### 6.2 毛色・ツヤ(A-2)
- 既存 7 毛色(`COAT`: 鹿毛/黒鹿毛/栗毛/栃栗毛/芦毛/青毛/白毛)を継承。マテリアルを `MeshLambertMaterial` → 軽い `MeshPhongMaterial`(低 `shininess≈18`、`specular` 弱)へ変更しツヤ付与。E-15 stage3 で Lambert へ戻す。

### 6.3 ゼッケン(A-4)
- **青地に白の馬番**(現行の白地黒数字 `numTexture` を改修): 128×128、地 `#1c4f9e`(青)、白縁、白数字 `bold 74px #fff`、下部に小さな飾り文字列(判読不能の様式、実在表記の複製をしない)。両側面(既存 `cloth` ×2)に表示。

### 6.4 勝負服バリエーション生成規則(A-5)
- 枠色に限定せず馬ごとに多彩化。決定的生成(同一馬=同一服): シード `seed = r.gate*2654435761 ^ hash(r.name)`。
  - 地色 `base` = パレット12色から `seed%12`。
  - 柄 `pattern ∈ {無地, 縦縞, 袖違い, 一本襷, 星散}` = `(seed>>4)%5`。
  - 帽子色 `cap` = **`WAKU_COLORS[r.waku-1]`(枠帽子は枠色=実際の競馬様式を踏襲)**。
  - 袖 `sleeve` = `base` の明暗変化 or 別パレット色。
- 生成は CanvasTexture 128×128(胴用)+帽子は単色マテリアル。ヘルメット・ゴーグルは既存騎手メッシュを継承。

### 6.5 顔白斑(A-3)
- 確率的・決定的付与: `seed` から `blaze ∈ {なし, 星(額の小円), 流星(鼻筋の縦帯), 鼻白(鼻端の白)}`。同一馬は常に同一(seed 固定)。
- 実装: 顔スカル用に白斑を描いた CanvasTexture(64×64、透明地+白形状)を毛色マテリアルに乗算 or 小白メッシュ。出走馬の 40〜60% に付与(AC-22 で確認できる程度)。

### 6.6 襲歩サイクル(A-6)
- 既存 `pose(phase, running)` を踏襲・強化。4拍ギャロップ:後肢(HL→HR)接地→前肢(FL→FR)接地、位相オフセット(HL:0, HR:+0.45, FL:π+0.35, FR:π+0.8)。
- **懸垂期**(4脚が地を離れる、A-6): `root.position.y` の上下動サイクルに、全脚が引き上がる位相窓(`sin(phase*0.5+φ)` のピーク付近で全脚 `knee` を屈曲)を設ける。ストライド周期は速度連動: `phase += v·dt·k`(`v`=各馬速度、既存は `m/3.4` の擬似連動 → 実速度 `sim.frames[].v` へ接続)。
- セカンダリ: 首の前後スイング、たてがみ・尾の揺れ(既存 tailPivot/neckPivot を継承)。

### 6.7 騎手モーション(A-7)
- 前傾騎乗(既存)。終盤(`R<400`)で「追う」動作: 腕・上体の周期プッシュ(`jockey.rotation` に `sin(phase)` プッシュ加算)。ゴール後(`sim.times[i]<t`)は立ち上がり流す(前傾角を緩める)。

### 6.8 群れの隊列力学(A-9)
- 横位置 `lat` は順位で内外へ配分(既存: `targetLat[hi] = 7.5 - 15·rank/(n-1)`)を継承しつつ、密集時の相互めり込み最小化のため近接反発(同 `m` 帯で `lat` 差 < 1.2m の馬同士を微小に押し分ける)を追加。Z-fighting 回避のため各馬 `m` に微小オフセット(`i·0.02m`)。最大18頭で破綻しない(AC-20)。内外の出し入れ(順位変動で `lat` が lerp)。

### 6.9 モーションブラー近似(A-8)
- 方式(いずれか併用、右ビュー側面クローズ/流し撮り時に発動):
  - (a) **背景水平流し**: 側面クローズ(L6/R-side)で、遠景ビルボードに進行方向逆向きの残像(半透明複製を 2〜3 枚オフセット描画)。
  - (b) **地面テクスチャ流し**: 走路テクスチャ UV を毎フレーム進行方向へスクロールし放射ブラー感(参考 #1 の放射状ブラー)。
  - (c) **脚部残像スプライト**: 高速時、脚下に半透明の掃引スプライト。
- AC-19 補助基準(背景が進行方向逆向きに流れる)を (a)/(b) のいずれかで満たす。

### 6.10 フォールバック(A-10)
- WebGL 不可時は既存スプライト馬(`spriteSide/spriteFront/spriteRear`)で全ショットを近似(§8)。

## 7. 性能予算

### 7.1 予算(WebGL 経路・両ビューポート合計、stage0)

| 指標 | 予算 | 手段 |
|---|---|---|
| draw call | ≤ 220 / フレーム(2パス合計) | ラチ・生垣・柵・竹を区間ごとに `BufferGeometry` マージ、`InstancedMesh` 活用。馬は共有ジオメトリ |
| 三角形 | ≤ 350k / フレーム | 遠景ビルボード化、`mFrom/mTo` 窓カリング(±350m)、LOD |
| テクスチャ | ≤ 24 枚、各 ≤ 512×512、VRAM < 48MB | 全 CanvasTexture キャッシュ、区間で共用 |
| 可視メッシュ | ≤ 150 / ビューポート | 視錐台+距離カリング |
| 馬 | 最大18頭、1頭 ≈ 20 メッシュ(共有geo) | ポーズ更新は毎フレーム1回、描画は2パス |

- フレーム構造: 「(1)シム位置更新→(2)左右カメラ解算→(3)馬ポーズ更新1回→(4)左viewport描画→(5)右viewport描画→(6)HUD描画」。(3)を2回描画で共有しCPU負荷を半減。

### 7.2 E-15 動的品質スケーリング(P0)

- **計測**: `rAF` 間隔の指数移動平均 `emaMs`(係数 0.1)。評価は 30 フレームごと。基準フレーム予算 `budget` = 16.7ms(PC)/33.3ms(モバイル、§1.4 判定)。
- **降格/昇格(ヒステリシス)**: `emaMs > budget·1.25` が連続2評価窓 → 1段降格。`emaMs < budget·0.7` が連続4評価窓 → 1段昇格。発動・段階をログ出力(`console.info("[E-15] quality→", level)`)し `SH._rvState.qualityLevel` に記録(AC-21)。

| stage(qualityLevel) | 無効化/縮退する機能 | DPR(q) |
|---|---|---|
| 0(full) | なし(影・グロー・全密度・デュアル) | 1.0 |
| 1 | **影**を無効(shadowMap off、ブロブ影のみ) | 1.0 |
| 2 | **グロー/ハロ/光条スプライト**を無効、フォグ簡略 | 0.75 |
| 3 | **ジオメトリ密度**削減(観客数半減・竹/木ビルボード間引き・馬セグメント低減・生垣インスタンス半減・Phong→Lambert) | 0.6 |
| 4(最終手段) | **単一ビュー化**(右ビューポート停止、左のみ全幅)。`qualityLevel=4` を記録(§1.3・AC-1) | 0.5 |

- 縮退順序 = 影→グロー→ジオメトリ密度→単一ビュー(要件 E-15 規定どおり、AC-21 で検証)。

`SH._render3d`(真偽、既存)に加え、`SH._rvState` オブジェクトをライブ中は毎フレーム末に更新。テストから参照可能。

## 8. フォールバック仕様(WebGL 不可)

- **判定**: 既存 `SH.Horse3D.available()`(`typeof THREE`)かつ `createRenderer` が非 null(`try/catch` で WebGL コンテキスト取得可)。いずれか失敗で `use3d=false`。加えて明示無効フラグ `SH._forceNoWebGL`(テスト用、AC-16)で強制フォールバック可。
- **動作**: `use3d=false` の場合、
  - デュアルビューを断念し**既存の単一ビュー番組構成**(2D スプライトレンダラー、1280×720 全幅)で完走(要件 P-8)。キャンバスは 1280×720 に戻す。
  - HUD は縮退版: **H-2(残距離)・H-6(経過タイム)・H-8(レース名)相当**を単一ビューに表示(P-8)。H-1帯・H-3隊列チップは既存 2D 版(現行 `drawOverlay` の隊列チップ・コースマップ)を流用。
  - 馬は `spriteSide/spriteFront/spriteRear`。カメラは既存 `computeCam`(gate/track/crane/stretch/goal)。
  - `SH._rvState.viewMode="single"`、`qualityLevel` は無効(WebGL非経路)だが `null` を設定。
- コンソールエラー0で完走(AC-16)。既存ゲームフロー(馬券→観戦→リプレイ→掲示板→払戻)は無退行(AC-15)。
