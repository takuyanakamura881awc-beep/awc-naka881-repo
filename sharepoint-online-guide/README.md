# Microsoft 365 モダンワークプレイス移行・活用ガイド

**― フェーズ1：基礎編（構成・棲み分け・権限設計）―**

オンプレミスのファイルサーバー中心の運用から、SharePoint Online / OneDrive / Microsoft Teams を中核とした Microsoft 365（以下 M365）の**推奨構成**へ移行・移り変わっていくための、汎用的な実務ガイドです。特定企業向けではなく、M365 をすでに利用中の一般的な国内企業が、自社の状況に合わせて読み替えて使えることを目指しています。

> 💡 **この資料の読み方（はじめにお読みください）**
> 本資料は SharePoint に詳しくない情報システム担当・IT 従事者の方でも読み進められるよう、随所に **【補足】** の枠で用語や背景をかみ砕いて説明しています。専門用語は巻末の [用語集](./99-glossary.md) にもまとめています。各説明の根拠となる Microsoft 公式ドキュメント等の出典は、文中に 〔S1〕 のような番号で示し、[出典一覧（Appendix）](./90-references.md) に集約しています。

---

## 1. 本資料の目的

- オンプレファイルサーバーの利用から、**SharePoint Online・OneDrive・Teams・その他 M365 アプリを適切に棲み分け**、Microsoft が推奨する構成・利用方法へ移行するための考え方を示す。
- 「SharePoint サイトを作る」と一口に言っても、**純粋な SharePoint サイト**（チームサイト／コミュニケーションサイト／組織全体サイト 等）と、**Teams チーム・プライベート/共有チャネルの裏側で自動生成される SharePoint サイト**があり、利用目的に応じてどちらを選ぶべきかの判断基準を提供する。
- 導入をいたずらに一度に進めず、**フェーズに分けて**段階的に成熟させる進め方を示す。本資料はその **フェーズ1（基礎）** を扱う。

## 3. 前提条件（本資料が想定する環境）

| 項目 | 前提 |
| --- | --- |
| 組織規模 | 従業員 **約 100〜1,000 名** の国内中堅企業 |
| テナント | **国内利用テナント／日本語 UI 前提** |
| ライセンス | **Microsoft 365 E3 を主体**（**300 席までの組織であれば** Business Premium 相当も概ね同様に読み替え可。Business Premium は 1 テナント最大 300 ユーザーの上限があるため、300 名超の帯では選択不可）。秘密度ラベル（社外秘/極秘等）の自動付与や高度な監査など、一部機能は **E5／E5 Compliance 相当が別途必要**であり、その旨は都度明記します。これらはフェーズ2以降の主題です。 |
| 現状 | オンプレファイルサーバーを主に利用。M365 はメール・Teams 等で一部利用開始済み。SharePoint Online の**クラシック形式サイト**が存在するケースも想定。 |

> 💡 **【補足】ライセンスの E3 / E5 とは**
> Microsoft 365 の企業向け主要プランです。ざっくり言うと、**E3** は Office アプリ＋ Teams/SharePoint/OneDrive などの基盤一式、**E5** はそれに加えて高度なセキュリティ・コンプライアンス・電話機能などが付く上位プランです。本フェーズ1（構成・棲み分け・権限）の内容は **E3 の範囲でほぼ実現できます**。

## 4. フェーズの全体像

本資料は成熟度を段階的に高めるアプローチを採ります。**フェーズ1〜4を収録**しています（フェーズ1が最重要のため最も厚く扱い、フェーズ4は任意）。各フェーズは前のフェーズの土台を前提とするため、順番に読むことを推奨します。

| フェーズ | 位置づけ | 主なテーマ | 状態 |
| --- | --- | --- | --- |
| **フェーズ1** | **基礎** | 全体構成、SharePoint/OneDrive/Teams の棲み分け、サイトの種類と選び方、Teams チャネル vs 純 SharePoint、情報アーキテクチャ、**グループ・権限設計**、クラシック→モダン移行の注意点、移行ツール選定 | **収録（第00〜04章）** |
| **フェーズ2** | セキュリティ | Office ファイルの「社外秘／極秘」等の**秘密度ラベル**（俗称：機密ラベル）によるタグ付け・保護、**監査ログ**の有効化、DLP、外部共有の厳格化、条件付きアクセス など | **収録（第10章）** |
| **フェーズ3** | ガバナンス・運用 | サイト/グループのライフサイクル（作成統制〜棚卸〜アーカイブ）、命名規則、プロビジョニング標準化、アクセスレビュー、運用体制 など | **収録（第20章）** |
| **フェーズ4（任意）** | 高度化・活用 | Copilot／AI 活用の前提整備、Power Platform 連携による業務自動化 など | **収録（第30章）** |

> ⚠️ **ライセンスに関する重要な前提**：フェーズ1は概ね **E3 の範囲**で実現できますが、**フェーズ2以降は E5／E5 Compliance／Microsoft Entra ID P2／SharePoint Advanced Management／Copilot 等の追加ライセンスを要する施策が増えます**。まず E3 でできることから着手し、追加投資は段階的に判断してください。
>
> **費用の表記（フェーズ2〜4 共通）**：各章の冒頭に「**この章でできること（全体像・図解）**」と「**追加費用の要否ひとめ表**」を用意し、次の2表記で一目で分かるようにしています。
> - **［E3標準］** … 追加費用なしで実施可能（現行の Microsoft 365 E3 の範囲）
> - **［要追加ライセンス］** … 別途の購入・契約が必要（E5／Entra ID P2／SharePoint Advanced Management／Copilot 等）

> 💡 **【補足】なぜフェーズを分けるのか**
> セキュリティ強化（フェーズ2）やガバナンス（フェーズ3）は、**土台となる構成・棲み分け・権限設計（フェーズ1）が固まって初めて有効に機能**します。順序を飛ばすと「ラベルは付けたが、そもそもサイトの分け方が不適切で権限が破綻」といった手戻りが起きます。まずフェーズ1で骨格を作ることが、後続の投資対効果を最大化します。
