## エグゼクティブサマリ

*（意思決定者向けの1ページ要約。詳細は各章を参照）*

- **課題**：オンプレミスのファイルサーバーは、テレワーク・社外アクセス、世代管理、検索性、バックアップ運用、機器更改コストの面で限界に達している。M365 をすでに契約している以上、同じ機能に二重投資している状態でもある。
- **目指す姿**：ファイルの置き場所を「**個人＝OneDrive／チーム＝SharePoint（多くは Teams 経由）／全社発信＝コミュニケーションサイト**」に整理し、Microsoft が推奨する**モダンでフラットな構成**へ移行する。これによりアクセス性・検索性・共同編集・ガバナンスを同時に底上げする 〔S1〕。
- **進め方**：一度に完璧を目指さず、**フェーズ1（基礎：構成・棲み分け・権限）→ フェーズ2（セキュリティ）→ フェーズ3（ガバナンス・運用）** と段階的に成熟させる。本資料はフェーズ1を扱う。
- **フェーズ1の要点（本資料の結論）**：
  1. **棲み分けを先に決める**。「どこに何を置くか」の原則を全社で共有してから移行する（第01章）。
  2. **サイトは基本『Teams チーム（＝グループ連携チームサイト）』または『コミュニケーションサイト』の2択**。用途で選ぶ。クラシックサイトやサブサイトは新規に作らない（第02章）。
  3. **権限は個人単位で付けず、Microsoft 365 グループ／セキュリティグループで束ねる**。フォルダ細分の代わりに「サイト／ライブラリ単位」で権限境界を設計する（第03章）。
  4. **クラシックからの移行は影響調査を先に**。移行ツールは無償の SPMT / Migration Manager を基本に、規模・要件次第で有償ツールを検討する（第04章）。
- **必要ライセンス**：フェーズ1の内容は **M365 E3 の範囲でほぼ実現可能**。高度なセキュリティ（機密ラベル自動付与・高度監査）はフェーズ2で E5 相当を検討する。
- **本フェーズで得られる効果**：脱ファイルサーバーによる運用・機器コスト削減、社外からの安全なアクセス、同時共同編集、バージョン履歴・ごみ箱による事故耐性、全文検索、そして後続のセキュリティ/ガバナンス施策が乗る「正しい土台」。

## 1. 背景 ― なぜ今、脱ファイルサーバーなのか

多くの企業が Microsoft 365 を契約済みでありながら、ファイルの実体は依然としてオンプレのファイルサーバー（Windows ファイルサーバー、NAS 等）に置いたままになっています。この状態には次の課題があります。

| 観点 | オンプレファイルサーバーの課題 |
| --- | --- |
| 社外アクセス | VPN 依存。テレワーク・出張・モバイルで使いづらく、VPN 集中による遅延も発生 |
| 共同作業 | 同時編集ができず「◯◯_最新_v3_確定版.xlsx」のような重複・世代混乱が起きる |
| 検索性 | 全文検索が弱く、目的のファイルにたどり着けない |
| 事故耐性 | 誤削除・上書きの復旧が運用（バックアップ）頼み。ランサムウェアの標的にもなりやすい |
| 権限管理 | 深いフォルダ階層に個別 ACL が積み重なり、誰が何にアクセスできるか不透明化 |
| コスト | ストレージ増設・機器更改・保守の継続的な費用。M365 との**二重投資** |

M365 の SharePoint Online / OneDrive / Teams へ移すことで、これらの多くが**追加コストなし（E3 に包含）**で解消・改善します。

> 💡 **【補足】SharePoint・OneDrive・Teams はそれぞれ別物？**
> 実は密接に連携する「ひとつの基盤」です。ファイルの**実体はすべて SharePoint（および OneDrive）に保存**され、Teams はその上で会話とファイルを束ねる“入れ物”として振る舞います。詳しくは [第01章](./01-architecture-and-workload-placement.md) で図解します。

## 2. 移行で目指す姿（ターゲット像）

Microsoft の推奨は、ファイルの性質に応じた明確な棲み分けです 〔S1〕。

- **個人の作業ファイル・下書き** → **OneDrive for Business**（本人所有。共有は都度）
- **チーム／部門で共有・共同編集するファイル** → **SharePoint のチームサイト**（多くは **Teams チーム経由**で作られる）
- **全社・部門から広く“発信・閲覧”させたい情報**（規程、ポータル、周知） → **コミュニケーションサイト／ホームサイト**

この3分類を全社の共通言語にすることが、移行成功の第一歩です。

| 含む | 含まない（後続フェーズ） |

| サイトの種類と選び方、Teams チャネルの裏側 | 監査ログの有効化・レビュー運用（→フェーズ2） |
| 情報アーキテクチャ（フラット構造・ハブ） | DLP・情報保護ポリシー（→フェーズ2） |

> 本資料は「**推奨構成＋鍵となる要点設定**」の粒度で書いています。考え方と“どう分けるべきか”を主眼に置き、管理センターの1クリック単位の操作手順は必要箇所に絞って触れます。実際の設定手順書は、方針確定後に対象テナント向けに別途作成することを想定しています。
